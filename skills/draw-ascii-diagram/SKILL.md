# 绘制纯文本流程图

根据当前任务的流程、调用链或业务规则画图。根据场景自己选择最合适的样式。优先直接输出 `text` 代码块，必要时补充简短图例。

## 样式与字符选择

| 场景 | 建议样式 | 常用字符 |
| --- | --- | --- |
| 逐步解释、附带接口或字段 | 纵向编号 | `[1]`、`\|`、`v` |
| 短流程、概览 | 横向链路 | `[步骤] --> [步骤]` |
| 强调节点边界 | ASCII 方框 | `+`、`-`、`\|` |
| 条件判断、互斥分支 | 决策节点与条件标签 | `<条件?>`、`--是-->`、`--否-->` |
| 分类路由、层级展开 | 树状分支 | `+--`、`\|`、反引号与 `--` 组合 |
| 同时执行、等待汇合 | 显式分叉与汇合节点 | `[FORK]`、`[JOIN: ALL]` |
| 重试、轮询、回到前一步 | 回边或节点引用 | `^`、`<--`、`(返回 [2])` |
| 跨服务交互、职责划分 | 泳道或时序列 | `\|`、`-->`、`<--`、`- - >` |
| Unicode线框、注重线框外观 | Unicode 线框 | `┌─┐`、`└─┘`、`├`、`┬`、`┼`、`│`、`→`、`↓`、`◇` |

## 示例

以下样式按场景选用，无需在一次回答中全部展示。示例中的重试上限、分支条件与等待规则均是假设输入已经给出的条件。
注意：示例仅演示排版。节点、接口、字段及业务关系来自当前任务，不复用示例中的业务内容，不擅自补充超时、重试次数等业务规则。

### 1. 纵向编号

```text
[1] 客户端请求网关
    API: /
    请求头: Authorization: Bearer <Token>
     |
     | (携带 Token)
     v
[2] 查询用户身份
    API: GET 员工查询接口
    查询: token=<Token>  =>  code=200, 读取 data.user
     |
     | (得到 user)
     v
[3] 返回用户身份
    输出: user
```

### 2. 横向紧凑链路

适合步骤少、每步名称短的概览。

```text
(开始) --> [读取配置] --> [解析内容] --> [生成结果] --> (结束)
```

### 3. ASCII 方框

严格 ASCII 输出可使用简短英文标签；需要中文解释时放在图外。

```text
+------------+     +------------+     +------------+
| Read input | --> | Transform  | --> | Save file  |
+------------+     +------------+     +------------+
```

### 4. 二选一决策与提前结束

两个出口分别标注条件，失败路径明确终止。

```text
[收到请求]
    |
    v
<凭证有效?> --否--> [返回错误] --> (结束)
    |
    是
    |
    v
[执行业务] --> [返回结果] --> (结束)
```

### 5. 多路互斥分支

树形排版表示分类路由；标注“仅选一条”，避免被理解为并行执行。

```text
[读取事件]
    |
    v
<事件类型: 仅选一条>
    |
    +-- created --> [创建记录] --> (结束)
    |
    +-- updated --> [更新记录] --> (结束)
    |
    +-- deleted --> [删除记录] --> (结束)
    |
    `-- 其他 ----> [记录未知类型] --> (结束)
```

### 6. 嵌套决策

后一个判断只发生在前一个判断的特定分支上。

```text
[提交操作]
    |
    v
<已登录?> --否--> [提示登录] --> (结束)
    |
    是
    |
    v
<有权限?> --否--> [拒绝访问] --> (结束)
    |
    是
    |
    v
[执行操作] --> (结束)
```

### 7. 互斥分支合流

两条路径只执行其中一条，随后进入同一个节点；合流处不等待另一条路径。

```text
                [1: Read]
                    |
                    v
                <Cached?>
                    |
          +-- yes --+-- no --+
          |                  |
          v                  v
     [2: Cache]         [3: Fetch]
          |                  |
          +---------+--------+
                    |
                    v
               [4: Return]
```

### 8. 并行分叉与等待全部完成

`FORK` 表示两条路径同时启动，`JOIN: ALL` 表示等待两个分支都完成。

```text
                [Start]
                   |
                   v
                 [FORK]
                   |
          +--------+--------+
          |                 |
          v                 v
      [Task A]          [Task B]
          |                 |
          +--------+--------+
                   |
                   v
              [JOIN: ALL]
                   |
                   v
               [Combine]
```

如果任务要求任意一个分支完成就继续，应改成 `JOIN: ANY`，并按已知规则注明其余分支继续还是取消；未知时标注待确认。

### 9. 循环与有限重试

用节点引用表达回边，避免长连线穿过多个决策。这里的“最多 3 次”包含首次调用。

```text
[1] 初始化 attempt = 0
     |
     v
[2] attempt += 1，调用服务
     |
     v
<调用成功?> --是--> [返回结果] --> (结束)
     |
     否
     |
     v
<attempt < 3?> --否--> [报告失败] --> (结束)
     |
     是
     |
     v
[3] 等待后重试
     |
     `-- (返回 [2])
```

### 10. 跨角色泳道与时序

从上往下表示时间推进；本图中实线表示请求，虚线表示响应。线型含义只适用于本图。

```text
Client              API                 DB
  |                  |                  |
  |--- request ----->|                  |
  |                  |--- query ------->|
  |                  |< - rows - - - - -|
  |< - response - - -|                  |
  |                  |                  |
```

### 11. Unicode 线框与决策（可选）

 Unicode 的纯文本图。`◇` 表示决策；“是”和“否”分别标在对应出口上。

```text
┌──────────┐
│ 提交申请 │
└────┬─────┘
     ↓
  ◇ 审核通过？ ──否──→ [退回修改] → (结束)
     │
     是
     ↓
┌──────────┐
│ 执行发布 │
└────┬─────┘
     ↓
   (结束)
```
